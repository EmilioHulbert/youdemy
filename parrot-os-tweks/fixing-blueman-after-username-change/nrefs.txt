The error you are seeing is not caused by a text file in `/etc`, but rather by a configuration setting stored in the `dconf` database (the system Linux uses to manage desktop application settings).

When you changed your username from `hulbert` to `remac`, the Blueman configuration for the **shared-path** (the folder where received Bluetooth files are saved) was not updated. It is still trying to point to `/home/hulbert/Desktop`, which no longer exists.

### How to Fix It

You can fix this by updating the `dconf` setting using the `gsettings` command in your terminal. Run the following command:

```bash
gsettings set org.blueman.transfer shared-path '/home/remac/Desktop'

```

*Note: Ensure that the directory `/home/remac/Desktop` actually exists. If you prefer to save files somewhere else, simply replace the path in the command above with the desired folder.*

---

### Why this happens

Most modern Linux desktop applications do not store their user-specific preferences in flat text files like those in `/etc`. Instead, they use **GSettings/dconf**. These settings are stored in a binary database file in your home directory (specifically `~/.config/dconf/user`). Because this database is not automatically updated when you change a username, you must manually point the software to the new path after such a migration.

If you encounter other issues with applications after a username change, they are likely also holding onto old paths in their GSettings keys. You can explore or change these settings using the **dconf-editor** tool (you may need to install it via your package manager) if you prefer a graphical interface to the command line.

You are correct that `blueman-applet` is a desktop application (a GUI taskbar element) rather than a system-level background service, which is why `systemctl` commands don't manage it directly.

When an application like this "fails" to start during login, it usually happens because the graphical session has already finished its initialization sequence. To get it running without rebooting or logging out, you have two primary options.

### 1. The Immediate Fix (Command Line)

Since you have already corrected the configuration path, you can simply kill any zombie processes that might still be hanging in the background and then restart the applet.

Run these commands in order:

```bash
# Terminate existing stuck blueman processes
killall blueman-applet
killall blueman-tray

# Launch the applet in the background
nohup blueman-applet > /dev/null 2>&1 &

```

*The `nohup` command ensures that even if you close your terminal window later, the applet continues to run.*

---

### 2. The Permanent Fix (Startup Applications)

If you want to ensure this loads automatically at every login, you need to verify the **Desktop Entry** file. Because you changed your username, any hardcoded paths in your autostart folder will still point to the old `/home/hulbert` location.

Check this directory for any Blueman-related files:
`~/.config/autostart/`

1. List the files: `ls ~/.config/autostart/`
2. If you see a file like `blueman.desktop`, open it: `nano ~/.config/autostart/blueman.desktop`
3. Look for any line starting with `Exec=` or any path references. If you see `/home/hulbert`, change it to `/home/remac`.

### Why `systemctl` didn't help here

You are encountering the difference between **System Services** and **Desktop Autostart**:

* **System Services (`systemctl`):** These are background processes managed by `systemd` (like `bluetooth.service`, which *is* the actual engine that connects your headphones/mice).
* **Desktop Autostart (`xdg-autostart`):** These are GUI apps (like `blueman-applet`, network-manager-applet, or wallpaper changers). They are launched by your Desktop Environment (GNOME, XFCE, KDE, etc.) once you have successfully logged in.

If `blueman-applet` continues to crash even after the `gsettings` fix, there might be a lock file or a temporary cache file holding the old path. You can clear the Blueman cache safely by running:
`rm -rf ~/.local/share/blueman`

After that, try running the `nohup` command again. Does the applet appear in your system tray now?
