To fix this systematically, you don't need to completely reinstall the operating system, but reinstalling mate-polkit or udisks2 and configuring a custom Polkit rule is the most reliable solution.
The core issue is that udisks2 (the system service that mounts drives) requires specific permissions via PolicyKit (polkit) to allow standard users to mount filesystems.
Step 1: Reinstall the Authentication Packages
First, force a clean reinstall of the authentication agent and disk management packages to restore any corrupted or missing system files:
bash
sudo apt update
sudo apt install --reinstall mate-polkit udisks2 policykit-1
Use code with caution.
(If you are on an Arch-based system, use sudo pacman -S mate-polkit udisks2, or sudo dnf reinstall ... on Fedora).
Step 2: Create a Specific Permission Rule (The Fix)
Polkit uses configuration files to decide who can mount a drive. Instead of modifying the system defaults (which get overwritten during updates), you should create a specific local override file.
Open a new configuration file in your terminal:
bash
sudo nano /etc/polkit-1/rules.d/99-allow-remac-mount.rules
Use code with caution.
Paste the following configuration exactly as shown. This explicitly gives your user (remac) or any user in the standard administrative group permission to mount internal and external drives without a prompt:
javascript
polkit.addRule(function(action, subject) {
    if ((action.id == "org.freedesktop.udisks2.filesystem-mount" ||
         action.id == "org.freedesktop.udisks2.filesystem-mount-system") &&
        subject.isInGroup("sudo")) {
        return polkit.Result.YES;
    }
});
Use code with caution.
(Note: If your system uses the wheel group instead of sudo for admin privileges, change "sudo" to "wheel").
Press Ctrl + O, then Enter to save, and Ctrl + X to exit.
Step 3: Verify the Config Files
Ensure your desktop environment is actually launching the agent when user remac logs in:
Look inside /etc/xdg/autostart/ for a file named mate-polkit.desktop or polkit-mate-authentication-agent-1.desktop.
If you are using a custom window manager (like i3, Openbox, or bspwm) instead of the full MATE desktop, you must manually add this line to your window manager's startup config file:

Use code with caution.
Step 4: Apply the Changes
For the new Polkit rules and reinstalled packages to take full effect, restart the Polkit service and restart Caja:
bash
sudo systemctl restart polkit
caja -q
Use code with caution.
Open Caja again and try clicking on your 54GB volume. It should now mount immediately without the authorization error.

On a slower external flash drive via a USB interface, Caja gets stuck in an input/output loop, causing the interface to lock up and become unresponsive.
Disabling this setting stops Caja from querying the folder metadata continuously.

When you click unmount, Caja sends a request to a background daemon called gvfsd (GNOME Virtual File System daemon). On your installed system, a stuck volume monitor loop is crashing or hanging whenever it tries to register an unmount signal from a removable block device, which freezes any open Caja windows.
Since changing the settings inside Caja failed, let's fix it by resetting the underlying desktop volume monitoring service back to factory defaults.
1. Reset the Desktop Volume Monitor Cache
Over time, gvfs builds a history of storage metadata, drive icons, and mounting endpoints in your user profile. If this cache is corrupted, it will lag out during device ejections.
Run these commands to wipe the local runtime volume monitor cache (this will not delete any of your files):
bash
# Force kill the hanging storage daemons
pkill -f gvfsd-disks
pkill -f gvfsd-computer

# Clear the local volume monitor state directories
rm -rf ~/.local/share/gvfs-metadata/*
rm -rf ~/.cache/gvfs/*
Use code with caution.
2. Kill and Reload the Desktop Session Services

bash
# Kill Caja completely
caja -q

# Restart the gvfs system daemon for your active session
gvfsd --replace &
Use code with caution.
