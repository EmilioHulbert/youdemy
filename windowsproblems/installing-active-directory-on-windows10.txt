Getting RSAT (Remote Server Administration Tools) on **Windows 10 Enterprise LTSC 2021** can be a real headache because LTSC often strips away the "easy" paths. Since you're on Build 19044 (21H2), you're dealing with the version where Microsoft moved RSAT into "Features on Demand" (FoD), meaning those old `.msu` installers you find online won't work anymore.

The most common reason this fails on LTSC is that your system is trying to talk to a corporate update server (WSUS) that doesn't have the RSAT files, instead of going to Microsoft directly.

Here is the "No-Nonsense" way to force it through.

---

### Method 1: The "Bypass & Force" PowerShell Method (Recommended)

This is the most reliable way for LTSC. It temporarily tells Windows to ignore your local update server and go straight to Microsoft to grab the AD tools.

1. Right-click **Start** and select **Windows PowerShell (Admin)**.
2. Copy and paste this entire block to bypass the WSUS restriction and install the Active Directory tools:

```powershell
# 1. Temporarily bypass WSUS/SCCM
$RegPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU"
$OldValue = (Get-ItemProperty -Path $RegPath).UseWUServer
Set-ItemProperty -Path $RegPath -Name "UseWUServer" -Value 0
Restart-Service wuauserv

# 2. Install Active Directory DS & LDS Tools
Add-WindowsCapability -Online -Name "Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0"

# 3. Restore your original update settings
Set-ItemProperty -Path $RegPath -Name "UseWUServer" -Value $OldValue
Restart-Service wuauserv

```

3. **Wait.** You'll see a progress bar. Once it hits 100%, the tools are installed. No reboot is usually required.

---

### Method 2: The "Offline" FoD ISO Method

If your machine has no internet access, you **must** use the "Features on Demand" ISO.

1. You need the **Windows 10 version 21H2 Features on Demand** ISO (Part 1).
2. Mount the ISO (Right-click > Mount). Let's assume it mounts as drive `E:`.
3. Run this PowerShell command:
`Add-WindowsCapability -Online -Name "Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0" -Source E:\ -LimitAccess`

---

### How to Find Them After Installation

Once the command finishes, you won't find an "RSAT" app. Instead, search your Start menu for:

* **Active Directory Users and Computers**
* **Group Policy Management**
* **Active Directory Administrative Center**

### Common Troubleshooting

* **Error 0x800f0954:** This means Method 1's registry bypass didn't take. Ensure you ran PowerShell as Administrator.
* **Error 0x8024402c:** This is a connection error. Ensure your machine can actually reach the public internet if you aren't using the offline ISO.

On LTSC versions, it's very common for this service to be set to "Disabled" to prevent forced updates, but `Add-WindowsCapability` **requires** that service to be active to fetch the files from Microsoft.

### The Fix: Enable the Service and Re-run

Run these commands in your **Admin PowerShell** window:

```powershell
# 1. Set the Windows Update service to Manual (so it CAN start)
Set-Service -Name wuauserv -StartupType Manual

# 2. Start the service
Start-Service wuauserv

# 3. Now, try the install again (using the bypass from before)
$RegPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU"
Set-ItemProperty -Path $RegPath -Name "UseWUServer" -Value 0

Add-WindowsCapability -Online -Name "Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0"

```

### If it still fails with "Access Denied" or "OpenError"

If you get an error specifically on the `Set-Service` line, it means your user account doesn't have the permissions to change service states, or a deep Group Policy is locking it.

**Quick check:**

1. Press `Win + R`, type **services.msc**, and hit Enter.
2. Scroll down to **Windows Update**.
3. Double-click it. Is the "Startup type" greyed out?
* **If yes:** You have a "hard" lock via Group Policy.
* **If no:** Change it to **Manual**, click **Apply**, and then try the PowerShell script again.

"Access Denied" when you're already an Administrator? That usually means your LTSC version has been "hardened" or a debloater script has locked the **Windows Update registry keys** specifically to prevent anyone (even you) from turning updates back on.

LTSC is like a fortress—sometimes it locks the owner out, too. We need to go around the side door and force the Registry to unlock the service.

### Step 1: Force the Service "Unlock" via Registry

Since `Set-Service` failed, we will use `reg.exe` to punch the value directly into the kernel. This usually bypasses the service manager's "Access Denied" block.

**Run these commands in your Admin PowerShell:**

```powershell
# 1. Force Windows Update (wuauserv) to Manual
reg add "HKLM\SYSTEM\CurrentControlSet\Services\wuauserv" /v Start /t REG_DWORD /d 3 /f

# 2. Force Background Intelligent Transfer (BITS) to Manual (Required for FoD)
reg add "HKLM\SYSTEM\CurrentControlSet\Services\bits" /v Start /t REG_DWORD /d 3 /f

# 3. Force Windows Modules Installer (TrustedInstaller) to Manual
reg add "HKLM\SYSTEM\CurrentControlSet\Services\trustedinstaller" /v Start /t REG_DWORD /d 3 /f

# 4. Now try to start the service again
net start wuauserv

```

---

### Step 2: Ensure WSUS is Bypassed

We need to make sure Windows isn't looking at a broken corporate update server.

```powershell
# Temporarily tell Windows to ignore WSUS and use Microsoft Servers
$RegPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU"
if (Test-Path $RegPath) {
    Set-ItemProperty -Path $RegPath -Name "UseWUServer" -Value 0
}

# Restart the service to apply the bypass
net stop wuauserv
net start wuauserv

```

### "Plan C": If you still get Access Denied

If the `reg add` commands above failed with "Access Denied," it means your registry permissions (ACLs) have been stripped. In that case, the only way to get RSAT is the **Offline Method**.

1. **Do you have the Windows 10 Features on Demand ISO?** (It’s usually named something like `Windows 10 Features on Demand, Part 1`).
2. If you have it, mount it.
3. Run this:
`DISM /Online /Add-Capability /CapabilityName:Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0 /Source:E:\ /LimitAccess`
*(Replace `E:\` with whatever drive letter the ISO mounted to).*
