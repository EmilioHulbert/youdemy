## What exactly is causing the delay

Most likely one (or more) of these:

1. **MSI deployment via GPO**

   * App pushed to computers (not users)
   * MSI hosted on:

     * Slow file share
     * DFS path
     * SYSVOL but large
     * Path that requires authentication before network is fully up

2. **Old or failed software assignment**

   * Package no longer exists
   * Version mismatch
   * Supersedence misconfigured
   * Waiting for rollback / repair

3. **“Always wait for the network at startup” is ENABLED**

   * This makes Software Installation *blocking*
   * Especially brutal on VMs

---

## Why it didn’t happen before domain join

Because **local Windows does not process Software Installation CSE at boot**.
Only domain-joined machines do.

## Fastest way to FIX it (without waiting for domain admins)

### 🔥 Option 1: Stop waiting for Software Installation at boot (most effective)

Run:

```cmd
gpedit.msc
```

Navigate to:

```
Computer Configuration
→ Administrative Templates
→ System
→ Group Policy
```

Set:

* **“Specify startup policy processing wait time”** → Enabled → `0`
* **“Always wait for the network at computer startup and logon”** → Disabled

Then:

```cmd
gpupdate /force
shutdown /r /t 0
```

⏱️ This alone usually drops boot time from minutes to seconds.

---

### 🔥 Option 2: Exclude THIS VM from the software GPO (clean solution)

If you have AD access:

1. Identify the **GPO name** applying Software Installation
2. Either:

   * Move VM to a different OU
   * Or add **Security Filtering → Deny Apply** for this VM
   * Or WMI filter (VM-only exclusion)

This is the **correct enterprise fix**.

---

### 🔥 Option 3: Temporary test (proof)

Boot **without network**:

* Disable VM NIC
* Restart
* Time the boot

You will see a **dramatic improvement**, confirming the policy block.
