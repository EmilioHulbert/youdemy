Final notes & gotchas (I’m blunt—read it)

The script looks for basename matches (e.g., hp_pavilion.jpg) inside text columns. This will catch rows that contain only filename, full path, or larger strings containing the filename. This avoids touching unrelated columns where .png appears in other contexts.

It only updates text-like columns (varchar/text). If you store file paths in JSON fields, jsonb or bytea, or in other encodings, this script will not find them. We can expand to JSON handling if needed.

Some WYSIWYG content may have HTML with <img src="...png">; this will be updated if the column contains that text.

You might still need to invalidate CDN cache / NGINX caches after the DB changes so clients request the new .webp files.

Older clients (rare) may not support .webp — consider <picture> or server-side content negotiation in the future.
